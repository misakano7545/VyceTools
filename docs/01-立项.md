# vyce-cloud-tool 立项说明

> 目标：在 vyce.cloud 放出免费 Vps-Mini 名额的瞬间自动抢到一台，供个人使用。
> 状态：M0 已完成（取证 + 只读监听器）；M1 待用户提供会话 Cookie 后联调下单。
> 日期：2026-10-22

---

## 1. 结论先说

**技术上完全可行，且成本极低**：放号状态由一个**公开、免登录**的接口 `GET /api/stock` 直接暴露（`free.open` 布尔值），下单只是一个 `POST /api/servers`。站点自己的前端就是每 30 秒轮询这个接口，所以“比人快”只需要把轮询压到 1–2 秒。

**但有三条硬约束决定了项目边界**（不是技术问题，是账号安全问题）：

1. ToS 明确「一人一号、一个免费服务器」，多开账号绕过限制是违规的 → **不做多账号、不做多开**。
2. 免费机每天要手动续期，且续期按钮**先弹广告再调 `/renew`** → 自动续期等于刷广告，**不做自动续期**，只做提醒。
3. `robots.txt` 对 `/api/` 是 `Disallow`，站点靠广告养免费机 → **轮询频率压在限流的 1/10 以内**，不做并发轰炸、不绕 Cloudflare。

在这个边界内，本工具是「个人用的库存监听 + 手速补足」，不是「批量薅号机器人」。

## 3. 范围

### 做
- **库存监听**：1–2 秒轮询 `/api/stock`，状态翻转（closed→open）立即本地告警。
- **一键开抢**：检测到 `free.open` 且某区域 `freeOpen=true` 时，自动 `POST /api/servers`（免费套餐、指定系统/区域/SSH key）。
- **结果落地**：拿到 `host:port` 与 root 密码/密钥信息，写入 `data/last-server.json` 并打印 SSH 命令。
- **放号统计**：把每次状态翻转写 `data/stock.jsonl`，`stats` 子命令算出每天几点放号、开了多久，用来回答「到底几点放」。
- **续期**：到期前自动 `POST /api/servers/{id}/renew`（M2，按用户要求加入；状态机与前端一致，回读校验后才算成功）。
- **便携**：纯 Python 3 标准库单文件，零第三方依赖，U 盘可带走，Windows 7 上的 Python 3.8 也能跑。

### 不做（明确非目标）
- 不多账号、不多开、不代注册 GitHub、不绕过 30 天账号限制。
- 不做并发轰炸 / 多 IP 轮询 / 绕过 Cloudflare 挑战。
- 不做 Web UI、不做数据库、不做常驻服务化（M3 才考虑计划任务）。
- 不碰付费套餐、不碰支付、不碰 `/me` 删除类接口。

## 4. 技术选型

**Python 3 标准库单文件**（`src/vyce.py`，`urllib` + `json` + `http.cookiejar`）。

理由：
- 零依赖 = 真正的便携（U 盘 + 任意 3.8+ 解释器即可），符合「轻量化运维、拒绝闭源二进制」的取向。
- 这个工具的全部复杂度是「定时 GET + 一次 POST」，用不上框架。
- 后续若要单文件免运行时，再补一个 Go 版本（源码同样开放），接口层完全一致。

**鉴权**：不做 OAuth 自动化（GitHub 有 2FA、设备验证，且自动化登录本身风险高）。改为**会话 Cookie 导入**：
- 浏览器登录一次 → 从 DevTools 复制 `Cookie` 请求头 → 存 `session.txt`（`.gitignore` 排除，权限 600）。
- 工具启动先 `GET /api/me` 验活；401 就提示重新导入。
- Cookie 只存在本机，不进日志、不进 git、不上传。

**反限流**：令牌桶，最小间隔 1.0s（默认 2.0s，约 30 次/分钟 = 限流的 10%）；遇 429 读 `Retry-After`/`x-ratelimit-reset` 退避；连续 3 次 5xx 指数退避。

## 5. 架构与主流程

```
            ┌──────────────┐   1–2s   ┌──────────────┐
            │  watcher     │─────────▶│ GET /api/stock│  (公开)
            └──────┬───────┘          └──────────────┘
                   │ open 翻转
                   ▼
            ┌──────────────┐  一次性  ┌──────────────────┐
            │  preflight   │─────────▶│ /me /servers /keys│ (Cookie)
            └──────┬───────┘          └──────────────────┘
                   │ 无免费机 + 有 key
                   ▼
            ┌──────────────┐   POST   ┌──────────────────┐
            │  deployer    │─────────▶│ POST /api/servers │
            └──────┬───────┘          └──────────────────┘
                   │ 轮询 GET /servers/{id}（3s，最多 10 分钟）
                   ▼
            data/last-server.json + 终端打印 ssh 命令 + 告警
```

关键判定（与前端保持一致）：
- 全局闸门：`stock.free.open === true && stock.free.enabled === true`
- 区域闸门：`region.freeOpen === true`，按 `region_preference` 顺序取第一个可用
- 幂等闸门：`GET /api/servers` 里已存在 `source === "free"` 的机器 → 不再下单（ToS 一人一台）
- 失败处理：`409/422`（没抢到）→ 记日志、回到监听；`401` → 停并提示重新导入 Cookie；`429` → 退避，不重试下单

## 10. M1 联调实录（2026-10-22，真实账号 + 真实接口）

会话 Cookie 导入后逐条打通，过程中发现 4 个只有实跑才会暴露的坑：

| # | 现象 | 原因 | 处置 |
|---|---|---|---|
| 1 | `POST /api/keys` → **403** `Cross-site requests are not allowed.` | 站点有同源 CSRF 校验，`urllib` 默认不带 `Origin` | 客户端统一加 `Origin`/`Referer` = `https://vyce.cloud` |
| 2 | 建机报 `ValueError: invalid literal for int()` | SSH key 的 `id` 是 **UUID**，不是自增整数 | 全链路按字符串处理 keyIds |
| 3 | `POST /api/servers` → **400** `Invalid option: expected one of "Ubuntu 24.04"\|...` | `os` 字段吃**展示名**，不是 `ubuntu-24` 这类 id（前端 state 存的正是 `Kg[].name`） | 加 `OS_OPTIONS` 映射，id 与展示名都接受 |
| 4 | 名额关闭时下单 → **503** `{"error":"no_stock"}` | 不是 409，是 503 | 视为「没抢到」，继续监听而不是崩 |

确认无误的完整错误契约：

- `401 unauthenticated` —— Cookie 失效 → 停并提示重导
- `403 Cross-site requests are not allowed.` —— 缺 Origin/Referer
- `400 invalid_request` + `fields:[...]` —— 参数不合法（os 名字写错等）
- `503 no_stock` —— 名额在提交瞬间被抢走
- `200` —— 建机成功，返回 `id`/`connect{host,sshPort}`/`credentials`

账号前置条件实测：GitHub 龄 906 天（≥30 天，合格）；初始 0 个 SSH key → 已用 `key-add` 登记本机 `id_ed25519.pub`；0 台服务器（未违反一人一台）。

至此除「真抢到一台」之外的每一步都已用真实会话验证：鉴权、CSRF、参数校验、库存闸门、错误分支。

## 11. M2 自动续期（参考 dengyie/vycebump）

参考实现：<https://github.com/dengyie/vycebump>（MIT，零依赖 Python，GitHub Actions 每 4 小时跑一次）。本工具只借它的**业务结论**，不复制代码。

### 从参考实现确认的三件事

1. **续期接口**：`POST /api/servers/{id}/renew`，带 Cookie + `Origin`/`Referer`；`200/204` 为成功，响应体可能为空。
2. **24 小时冷却的判定不靠接口，靠 `expiresAt`**：免费机初始存活 48 小时，`expiresAt - now > 24h` 即处于冷却期，不能续；`≤ 24h` 才进续期窗口。续期成功后 `expiresAt` 重置为 now+48h（前端提示语「Renewed for 2 days」）。
3. **`429` 是常态不是故障**：服务端用 `429 renewal_cooldown` / `wait N more hours` 表达冷却未到，必须与真正的限流区分开。

### 与前端状态机逐条对齐

反编译 bundle 里的 `Hy(e,t)`，得到官方判定（`Ly`=1 天、`zy`=1 天、`Ry`=2 天、`Iy`=1 小时）：

```
source!=free || suspended || status==creating → none
status!=running                              → stopped  (可续)
expiresAt-now <= 0                           → late     (可续，stopIn 用 stopsAt)
expiresAt-now > 1 天                          → cooldown (不可续)
expiresAt-now <= 6 小时                       → soon     (可续)
其余                                          → ok       (可续)
```

本工具的 `renew_state()` 逐条复刻，并用 6 个单元测试锁死边界（含「恰好 24 小时」「suspended」「creating」）。

### 广告门：实测确认为纯前端

前端续期函数 `Wy(e)`：

```js
let t = `vyce_renew_ad_${e.id}`;
if (!sessionStorage.getItem(t)) {
  sessionStorage.setItem(t, 1);
  window.open('https://uplcm.com/4/11978746', '_blank', ...);  // 弹广告
  K.info('Sponsor link opened. Press Renew again to complete renewal.');
  return;                                                      // 首次点击只弹广告，不续期
}
await C_(e.id);   // 第二次点击才真的 POST /renew
```

结论：**广告门是浏览器端的 `sessionStorage` 逻辑，接口本身不校验任何广告令牌**。因此脚本直接调 `/renew` 可以续期，但不会产生广告曝光。这是本工具唯一一处绕开站点变现路径的行为——已按用户明确要求实现，风险记录在 §7 风险表，不隐瞒。

### 实现要点

- `renew` 一次性检查；`renew --loop` 常驻（默认 30 分钟一轮）；`watch --deploy --renew` 单进程同时管抢机和续期。
- **续期后必须回读**：`POST` 返回 200 后重新 `GET /api/servers`，比对 `expiresAt` 是否真的推进；没推进就记 `renewed_unverified` 并计为失败（不接受「接口说成功」）。
- 状态落 `data/renew_state.json`（含 `next_renewal_ts`，供下一轮跳过冷却）。
- 错误分支：`401` 停并提示重导 Cookie；`404` 说明机器已消失，清记录；`429 renewal_cooldown` 按 `wait N more hours` 排下次窗口，不计失败。

### 验证状态（诚实标注）

- ✅ 18 个离线测试全过（含续期 15 个：状态机 6、`renew_once` 8、冷却识别 1）。
- ✅ 真实会话实测：`GET /api/servers` → `{"servers":[]}`；`POST /api/servers/<uuid>/renew` → `404 not_found`；非 UUID → `400 Invalid UUID`。
- ⏳ **未验证**：真机上的成功续期（账号当前 0 台服务器，抢到后才能跑通 `200 → expiresAt 推进` 这一段）。这一段代码路径目前只有 FakeApi 覆盖，等抢到机立刻补测。

### 实测规格（通过站点 Web 终端取得）

```
Ubuntu 24.04.5 LTS | x86_64 | 1 vCPU | 2048 MB RAM | 6.5 GB 磁盘（已用 8%）
load average: 14.66, 20.92, 21.67   ← 1 核跑 15–21 的负载，明显是超卖的共享节点
```

### 抢机环节踩到的坑（已修）

`POST /api/servers` 返回的是 **`{server: {...}, credentials: {...}}`**，不是裸 server 对象。前端 `g_` 里写得很清楚：`return {...t.server, credentials: t.credentials}`。第一版直接读 `payload["id"]` 得到 `None`，于是后续 `GET /api/servers/None` 全部 `400 Invalid UUID`，机器虽然开出来了但脚本完全不知道 —— 这次是靠人工看日志才发现的。

修法：`unwrap_created()` 统一拆包 + 兜底「回读 `/api/servers` 取最新免费机」，并补了 4 个离线测试（含「已有免费机必须拒绝下单」的幂等闸门）。

### 连通性：免费机是 IPv6-only，且本机到该地址不通

- `connect`（IPv4 host/sshPort）为 **null**，只有 `ipv6: 2a11:6c7:1105:1906::288`。前端逻辑也是 `e.ipv6 ? ssh root@${e.ipv6} : connect ? ssh -p ${connect.sshPort} ...`。
- 本机 IPv6 出网正常（`curl -6 https://ipv6.icanhazip.com` 返回 `2408:865c:...`）。
- 但对该地址 22/80/443/2222/10022/20000 全部 TCP 超时 —— 家宽到该机房前缀无路由或被丢包。
- 站点自带 **Terminal 标签页**（`wss://vyce.cloud/api/servers/{id}/terminal`）可用：实测拿到 `root@vm-7ff1fd84bab8` 的 shell，跑通了 `hostname` / `id` / `free` / `df` / `uptime`。

**结论**：这台机器从本机 SSH 连不上，日常操作走浏览器里的 Terminal 标签页。若必须 SSH，得换有该前缀可达性的网络（移动网络/另一条线路）或让机器自己反连出来。

> 曾尝试把 WebSocket 终端封装成 CLI 的 `term` 子命令，但该端点在站点高负载下时序不稳（命令只回显不执行），可靠性不够，**没有并入工具**。浏览器 Terminal 是可靠路径。

## 13. 自定义区域（M2.1）

### 为什么不是改 `region_preference` 就够

原实现里 `region_preference` 只是**排序**：列表里没有的区域会被追加到末尾，照样会抢。用户想要「只要 Asia」时，这个语义是错的 —— 他会以为限定住了，实际照样抢到 Europe。所以拆成两个概念：

| 概念 | 配置/参数 | 语义 |
|---|---|---|
| 排序 | `region_preference` | 同一批候选里的先后顺序，不限制范围（保持旧行为） |
| 白名单 | `region_allow` / `--region` | 严格限定，范围外一律不下单 |

`--any-region` 用来临时清空两者，回到「哪个区先开抢哪个」。

### 实现要点

1. `region_pool(snap, pref, allow)` 产出有序候选池，`free_regions()` 在其上按 `freeOpen` 过滤 —— 两处逻辑合一，避免 dry-run 与真实下单算出不同结果。
2. `normalize_regions(values, known, strict)` 做大小写/别名归一化。**白名单严格、偏好宽松**：`--region` 打错字直接 `die`，`region_preference` 里的历史区域名只 warn 后忽略（站点改名不该让老配置直接崩）。
3. 站点区域列表来自 `/api/stock`，所以 `watch` 在**第一次轮询后**才做校验，不额外多发一个请求。
4. `stock.jsonl` 拆成两个字段：`free_regions`（实际开放的全部区域）+ `eligible_regions`（白名单过滤后）。限定区域的用户不会因此丢掉放号统计样本。
5. 白名单外放号时的日志是明确的一句话，而不是笼统的「名额关闭」：
   `[!] 名额开在 Asia，但不在你指定的区域 Europe 内，跳过本轮`
